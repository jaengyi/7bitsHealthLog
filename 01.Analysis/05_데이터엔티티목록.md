# 데이터 엔티티 목록

**개인용 운동기록 애플리케이션 (가칭 MyFit) · v1.0**

> 본 문서는 `01.Analysis/운동기록앱_요구사항정의서_기능정의서_v1.0.xlsx` 의 **데이터엔티티목록** 시트를 Markdown으로 옮긴 산출물이다.
> 원본 셀 내용은 가감 없이 그대로 반영하였으며, 가독성을 위해 분류 단위로 절을 나누었다.


- 논리 데이터 모델 **초안**이다. 상세 ERD 및 컬럼 정의서(자료형·제약조건·인덱스)는 별도 산출물로 작성한다.
- **총 24개 엔티티** — Phase 1 12개 / Phase 2 7개 / Phase 3 5개

## 3. 핵심 관계 개요

```
user (ENT-001)
 ├─1:1─ user_setting (ENT-002)
 ├─1:N─ workout_log (ENT-008) ─1:N─ workout_log_exercise (ENT-009) ─1:N─ workout_set (ENT-010)
 ├─1:N─ routine (ENT-011) ─1:N─ routine_exercise (ENT-012)
 ├─1:N─ program (ENT-013) ─N:M─ program_routine (ENT-014) ─ routine
 ├─1:N─ personal_record (ENT-015)
 ├─1:N─ body_composition (ENT-016) / body_measurement (ENT-017) / body_photo (ENT-018)
 ├─1:N─ diet_log (ENT-020) ─1:N─ diet_log_item (ENT-021) ─N:1─ food (ENT-019)
 └─1:N─ user_plate (ENT-022)

exercise (ENT-003)
 ├─N:M─ exercise_body_part (ENT-005) ─ body_part (ENT-004)
 ├─1:N─ exercise_note (ENT-007)   # PT 학습 노트
 ├─N:M─ exercise_favorite (ENT-006)
 └─1:N─ workout_log_exercise / routine_exercise / personal_record

sync_state (ENT-023), tombstone (ENT-024)  # 동기화 전용 메타 엔티티
```

## 4. 설계 유의사항

- **UUID 기반 PK**: `user`, `workout_log`, `workout_set` 등 동기화 대상 엔티티는 UUID를 PK로 사용하여
  기기 이전·복수 기기 동기화 시 중복이 발생하지 않도록 한다. (REQ-DAT-004)
- **논리 삭제 원칙**: 기록이 참조하는 마스터(`exercise`, `routine`)는 물리 삭제 대신 `is_active=false` 로 처리한다.
  (REQ-EXR-004, FN-RTN-004)
- **tombstone**: 삭제 사실을 서버로 전파하기 위해 삭제 시 `tombstone` 레코드를 남긴다. (REQ-DAT-002)
- **updated_at 필수**: 동기화 대상 전 엔티티는 `updated_at` 컬럼을 보유하여 Last-Write-Wins 충돌 해소의 기준으로 사용한다.
- **세트 엔티티 확장성**: 종목 기록유형(중량+횟수 / 횟수 / 시간 / 거리+시간 / 중량+시간)에 따라 사용 컬럼이 달라지므로
  `workout_set` 은 유형별 컬럼을 nullable 로 보유하는 확장 가능 구조로 설계한다. (REQ-NFR-006, REQ-EXR-007)
- **SI 단위 저장**: 중량은 kg, 길이는 cm, 거리는 km 로 저장하고 표시 시점에 변환한다. (REQ-CMN-003)

- 관련 요구사항은 [요구사항정의서](./02_요구사항정의서.md), 기능은 [기능정의서](./03_기능정의서.md) 참조.
