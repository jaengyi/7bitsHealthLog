
산출물: `app/build/outputs/apk/release/app-release.apk`

| 항목 | 값 |
|---|---|
| versionName | `1.0.0` |
| versionCode | `1` |
| applicationId | `com.sevenbits.myfit` |
| APK 크기 | **7.1 MB** (debug 28.1 MB) |
| minSdk / targetSdk | 26 / 36 |

R8 코드 축소와 리소스 축소가 적용되어 debug 대비 **약 1/4** 크기다.
가이드 이미지 219장(4.73 MB)이 대부분을 차지한다.

## 2. 서명 키 관리

### 2.1 키 정보

| 항목 | 값 |
|---|---|
| 키스토어 | `C:/03.Project/myfit-keys/myfit-release.jks` |
| 별칭 | `myfit` |
| 알고리즘 | RSA 4096 |
| 유효기간 | 10,950일 (약 30년) |
| 인증서 DN | `CN=MyFit, OU=7bits, O=7bits, L=Seoul, C=KR` |
| SHA-256 지문 | `c0:03:81:68:68:eb:05:14:b3:58:20:b2:8f:55:10:bb:63:90:5f:a2:8c:bf:41:27:5f:a4:0b:5f:7c:f6:35:58` |

### 2.2 ⚠️ 반드시 백업할 것

**키스토어와 비밀번호를 잃어버리면 같은 서명으로 업데이트를 낼 수 없다.**
기존 설치본 위에 덮어쓰기가 불가능해지고, 사용자는 앱을 지우고 다시 설치해야 한다
(= 로컬 데이터 전부 소실). Play Store에 올린 뒤라면 그 앱은 영영 갱신할 수 없다.

백업 대상 두 가지:

1. `C:/03.Project/myfit-keys/myfit-release.jks`
2. `03.Implement/myfit-android/keystore.properties` (비밀번호가 들어 있다)

저장소 밖의 안전한 곳(외장 디스크·비밀번호 관리자)에 보관한다.
두 파일 모두 **`.gitignore` 대상**이며 커밋되지 않는다.

### 2.3 주입 방식

빌드 스크립트가 다음 순서로 서명 정보를 찾는다.

| 순위 | 위치 | 용도 |
|---|---|---|
| 1 | `myfit-android/keystore.properties` | 로컬 개발 |
| 2 | 환경변수 `MYFIT_STORE_FILE` 등 4종 | CI Secret |
| 3 | 없으면 debug 키 + 경고 로그 | 신규 참여자 |

키가 없다고 빌드를 깨뜨리지 않는다. 저장소를 새로 받은 사람이 프로젝트를
열어 볼 수조차 없게 되는 쪽이 더 나쁘다. 대신 경고를 남긴다.

CI에서 쓸 때:

```bash
export MYFIT_STORE_FILE=/path/to/myfit-release.jks
export MYFIT_STORE_PASSWORD=***
export MYFIT_KEY_ALIAS=myfit
export MYFIT_KEY_PASSWORD=***
```

## 3. 실기기 설치

```bash
# USB 디버깅을 켠 상태에서
adb install -r 03.Implement/myfit-android/app/build/outputs/apk/release/app-release.apk
```

또는 APK 파일을 기기로 옮겨 직접 설치한다("출처를 알 수 없는 앱" 허용 필요).

> debug 빌드는 `applicationId` 에 `.debug` 접미사가 붙어 **릴리즈 빌드와 동시 설치가
> 가능하다**. 개발 중 데이터와 실사용 데이터가 섞이지 않는다.

## 4. 실기기 검증 시나리오

**릴리즈 판정 기준: 운동 1회 완주.** 순서대로 확인한다.

| # | 단계 | 확인할 것 |
|---|---|---|
| 1 | 최초 실행 | 온보딩 4단계가 뜨고, 건너뛰어도 진행된다 |
| 2 | 시드 적재 | 종목 219개가 보인다. 첫 실행이 과도하게 느리지 않다 |
| 3 | 종목 검색 | "벤치" 및 초성 "ㅂㅊ" 로 결과가 나온다 |
| 4 | 자세 가이드 | 이미지가 **비행기 모드에서도** 표시된다 |
| 5 | 종목 추가 | 일지에 담기고, 직전 기록이 프리필된다 |
| 6 | 세트 입력 | ± 버튼 반응이 즉각적이다. 뒤로 갔다 와도 값이 남아 있다 |
| 7 | 운동 시작 | 수행 화면으로 이동하고 화면이 꺼지지 않는다 |
| 8 | 세트 체크 | 휴식 타이머가 자동 시작된다 |
| 9 | **백그라운드 타이머** | 홈으로 나가도 알림에 잔여 시간이 갱신된다 |
| 10 | 타이머 정확도 | 화면을 껐다 켜도 시간이 밀리지 않는다 |
| 11 | 앱 강제 종료 후 재진입 | 하던 종목·세트 자리로 돌아온다 |
| 12 | 운동 종료 | 요약 화면에 볼륨·세트·부위 비중이 나온다 |
| 13 | 루틴 저장 | 요약에서 저장한 루틴이 루틴 탭에 보인다 |
| 14 | 루틴 실행 | 루틴이 새 일지로 복제된다 |
| 15 | 캘린더 | 수행한 날짜에 마커가 찍힌다 |
| 16 | 설정 반영 | 증감 단위·휴식시간을 바꾸면 실제로 달라진다 |
| 17 | 테마 | 라이트/다크 전환이 즉시 반영된다 |

**R8 난독화 이후에만 드러나는 문제**를 특히 주의해서 본다. 아래는 릴리즈
빌드에서만 깨질 수 있는 지점이다.

| 위험 지점 | 증상 |
|---|---|
| 시드 JSON 파싱 | 최초 실행 시 종목 목록이 비어 있음 |
| Navigation 타입 안전 라우트 | 화면 이동 시 직렬화 오류 |
| Room 스키마 | DB 생성 실패로 앱 시작 불가 |

세 가지 모두 `proguard-rules.pro` 에 keep 규칙이 있으나,
**실기기 실행으로만 최종 확인된다.**
