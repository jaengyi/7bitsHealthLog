## 1. 요구사항

`REQ-NFR-001` 화면 응답 성능 (중요도 상 / Phase 1)

> 운동일지 화면 진입 1초 이내, 세트 입력 후 화면 반영 100ms 이내, 종목 검색 결과 표시 300ms 이내.
> 기록 3년치(약 30,000 세트) 누적 상태에서도 동일 기준을 충족한다.

---

## 2. 측정 데이터 규모

3년치 누적 상태를 재현한다.

| 항목 | 수량 | 산출 근거 |
|---|---:|---|
| 사용자 | 1 | 로컬 단일 사용자 |
| 종목 | 30 | 실제 사용자가 반복 수행하는 종목 수 |
| 운동일지 | 500 | 이틀에 한 번 × 약 3년 |
| 일지-종목 | 3,000 | 일지당 6종목 |
| **세트** | **30,000** | 종목당 10세트 |

요구사항의 "약 30,000 세트"를 정확히 충족한다.

---

## 3. 측정 결과

측정값은 워밍업 1회 후 5회 실행의 **중앙값**이다. 첫 실행에는 JIT 컴파일과
쿼리 계획 수립 비용이 섞여 있어 평균보다 중앙값이 실제 사용 경험에 가깝다.

| 측정 항목 | 관련 화면 | 측정값 | 예산 | 여유 |
|---|---|---:|---:|---:|
| 일지 상세 조회 | SCR-WRK-001 진입 | **21 ms** | 500 ms | 24배 |
| 세션 집계 | SCR-WRK-001 하단 요약 | **2 ms** | 100 ms | 50배 |
| 세트 단건 갱신 | SCR-WRK-002 입력 반영 | **4 ms** | 50 ms | 12배 |
| 월간 캘린더 요약 | SCR-CAL-001 | **3 ms** | 300 ms | 100배 |
| 종목 검색 | SCR-EXR-001 | **2 ms** | 300 ms | 150배 |
| 직전 수행 세트 조회 | 종목 추가 시 프리필 | **10 ms** | 300 ms | 30배 |

**전 항목 통과.**

### 예산을 요구사항보다 낮게 잡은 이유

여기서 재는 것은 **DB 왕복 시간뿐**이다. 사용자가 체감하는 화면 응답에는
Compose 렌더링·상태 전파가 더해진다. 그래서 임계값을 요구사항의 절반 이하로
잡았다 — DB가 예산의 절반을 먹기 시작하면 이미 위험 신호다.

## 4. 측정의 한계

정직하게 적어 둔다.

| 한계 | 영향 |
|---|---|
| **인메모리 SQLite** | 디스크 I/O가 빠진다. 실기기 값은 이보다 크다 |
| **JVM(데스크톱) 실행** | 모바일 CPU보다 빠르다 |
| **DB 계층만 측정** | UI 렌더링 시간이 빠져 있다 |
| **콜드 스타트 미측정** | 앱 최초 실행 시 시드 적재 시간은 별도 항목 |

이 테스트가 잡으려는 것은 **절대 시간이 아니라 "행 수에 비례해 느려지는 쿼리"**다.
인덱스가 빠지거나 N+1 쿼리가 들어오면 30,000행에서 즉시 드러난다. 절대 시간에 대한
판단은 12단계 실기기 검증에서 확정한다.

---

## 5. 성능을 지탱하는 설계 결정

측정값이 좋은 것은 우연이 아니라 아래 결정들의 결과다.

| 결정 | 위치 | 효과 |
|---|---|---|
| 집계는 전부 SQL `GROUP BY` | `WorkoutDao.aggregateSession` | 세트 30,000행을 앱 메모리로 올리지 않는다 |
| 일지 상세는 `@Transaction` 단일 조회 | `WorkoutDao.observeLogDetail` | 종목 6개 × 세트 10개를 왕복 1회로 가져온다 |
| 매핑·즐겨찾기 일괄 조회 | `ExerciseLocalSource.enrich()` | 검색 결과 50건에 대한 N+1을 없앤다 |
| 초성 인덱스 컬럼 사전 계산 | `exercise.name_chosung` | 검색 시점에 초성을 추출하지 않는다 |
| 날짜·상태 복합 인덱스 | `workout_log` | 캘린더 범위 조회가 전체 스캔으로 가지 않는다 |

---

## 6. 회귀 방지

`PerformanceTest` 는 일반 단위 테스트와 함께 실행된다. 임계값을 초과하면
**빌드가 실패한다** — 성능 저하가 리뷰를 통과해 들어오는 것을 막는다.

적재 비용(30,000행)이 있어 클래스당 1회만 시드하며, 전체 실행 시간은 약 30초다.
