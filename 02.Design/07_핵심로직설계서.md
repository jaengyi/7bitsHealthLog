## 1. 추정 1RM (One Rep Max)

### 1.1 산출식 (FN-RPT-001, FN-RPT-002)

| 공식 | 산출식 | 특성 |
|---|---|---|
| **Epley** (기본값) | `1RM = w × (1 + r / 30)` | 고반복에서 값이 크게 나옴. 가장 보편적 |
| **Brzycki** | `1RM = w × 36 / (37 − r)` | 저반복(≤10)에서 정확도 우수. `r ≥ 37` 정의 불가 |
| **Lombardi** | `1RM = w × r^0.10` | 보수적 추정. 고반복에서 완만 |

```kotlin
// :core:domain/calculator/OneRepMaxCalculator.kt
object OneRepMaxCalculator {

    fun estimate(weightKg: Double, reps: Int, formula: OneRmFormula): Double? {
        if (weightKg <= 0.0 || reps <= 0) return null
        if (reps == 1) return weightKg            // ★ 1회는 실측값 그대로 (공식 보정 배제)

        return when (formula) {
            OneRmFormula.EPLEY    -> weightKg * (1 + reps / 30.0)
            OneRmFormula.BRZYCKI  -> if (reps >= 37) null else weightKg * 36.0 / (37.0 - reps)
            OneRmFormula.LOMBARDI -> weightKg * reps.toDouble().pow(0.10)
        }.let { round1(it) }                      // 소수 1자리 반올림
    }

    /** 추정 신뢰도 (FN-RPT-003) */
    fun confidence(reps: Int): Confidence = when {
        reps <= 5  -> Confidence.HIGH
        reps <= 12 -> Confidence.NORMAL
        else       -> Confidence.LOW              // 12회 초과 → UI에 ⚠️ 표기
    }
}
```

**`reps == 1` 특례 사유**: Epley 공식에 `r=1` 을 대입하면 `w × 1.033` 이 되어 실제 1RM 실측값보다 3.3% 높게 나온다.
1회 수행은 그 자체가 1RM이므로 공식을 적용하지 않는다.

### 1.2 종목 추정 1RM (분석 기준값)

세트마다 추정값이 다르므로, **종목 단위 대표 1RM** 은 다음으로 정의한다.

```
종목 추정1RM = MAX( estimate(set) )   for set in 최근 90일 && set_type != 'WARMUP' && reps <= 12
```

- 웜업 세트 제외 (REQ-WRK-004)
- 12회 초과 세트는 신뢰도가 낮으므로 **대표값 산출에서 제외**한다(표시는 하되 기준으로 쓰지 않음)
- 90일 창을 두는 이유: 1년 전 기록을 현재 강도 기준으로 쓰면 %1RM이 왜곡된다

|---:|---:|---|---:|
| 100 | 1 | Epley | **100.0** (특례) |
| 100 | 10 | Epley | 133.3 |
| 100 | 10 | Brzycki | 133.3 |

## 2. 볼륨 (Volume)

### 2.1 산출식 (REQ 용어정의, FN-WRK-027)

```
세트 볼륨   = weight_kg × reps
종목 볼륨   = Σ(세트 볼륨)        where set_type != 'WARMUP'
세션 볼륨   = Σ(종목 볼륨)
```

```kotlin
object VolumeCalculator {
    fun setVolume(set: WorkoutSet): Double =
        if (set.setType == SetType.WARMUP) 0.0
        else (set.weightKg ?: 0.0) * (set.reps ?: 0)

    fun totalVolume(sets: List<WorkoutSet>): Double =
        sets.sumOf { setVolume(it) }
}
```

| 규칙 | 내용 |
|---|---|
| **웜업 제외** | `WARMUP` 세트는 볼륨 0 (REQ-WRK-004, FN-WRK-013) |
| **드랍/실패 포함** | `DROP`, `FAILURE` 는 실제 수행한 작업량이므로 **포함** |
| **중량 없는 종목** | `REPS_ONLY`(맨몸), `TIME` 종목은 볼륨 집계에서 제외(중량 NULL → 0) |
| **미완료 세트** | 계획만 하고 완료하지 않은 세트도 값이 입력되어 있으면 포함. 단 **수행 중 화면의 실시간 볼륨은 `is_completed=1` 만 합산** |

> **집계 위치**: SQL `SUM(weight_kg * reps)` 로 DB에서 수행한다(REQ-NFR-001).
> 위 Kotlin 함수는 수행 중 실시간 갱신과 단위 테스트용이다.

## 3. 강도 (Intensity, %1RM)

### 3.1 산출식 (FN-RPT-004~006)

```
세트 강도(%)   = weight_kg ÷ 종목추정1RM × 100
세션 평균 강도 = Σ(세트강도 × 세트볼륨) ÷ Σ(세트볼륨)     ← 볼륨 가중평균, 웜업 제외
```

> **가중평균을 쓰는 이유**: 단순 평균은 1회짜리 고중량 세트와 12회짜리 저중량 세트를 동일 취급한다.
> 볼륨 가중을 적용해야 세션의 실제 부하 성격이 반영된다.

### 3.2 강도 구간 (FN-RPT-006)

| 구간 | 범위 | 훈련 성격 |
|---|---|---|
| **근력 (Strength)** | ≥ 85% | 고강도 저반복 |
| **근비대 (Hypertrophy)** | 65% ~ 85% 미만 | 중강도 중반복 |
| **근지속력 (Endurance)** | < 65% | 저강도 고반복 |

```kotlin
object IntensityCalculator {
    fun intensityPct(weightKg: Double, e1rm: Double): Double? =
        if (e1rm <= 0.0) null else round1(weightKg / e1rm * 100.0)

    fun zone(pct: Double): IntensityZone = when {
        pct >= 85.0 -> IntensityZone.STRENGTH
        pct >= 65.0 -> IntensityZone.HYPERTROPHY
        else        -> IntensityZone.ENDURANCE
    }

    fun sessionAvgIntensity(sets: List<WorkoutSet>, e1rmOf: (String) -> Double?): Double? {
        val valid = sets.filter { it.setType != SetType.WARMUP && it.weightKg != null && it.reps != null }
        if (valid.isEmpty()) return null
        var weightedSum = 0.0; var volumeSum = 0.0
        valid.forEach { s ->
            val e1rm = e1rmOf(s.exerciseId) ?: return@forEach
            val vol = s.weightKg!! * s.reps!!
            weightedSum += (s.weightKg!! / e1rm * 100.0) * vol
            volumeSum += vol
        }
        return if (volumeSum == 0.0) null else round1(weightedSum / volumeSum)
    }
}
```

|---:|---:|---:|---|

## 4. 세션 요약 (FN-WRK-027, FN-WRK-028)

```kotlin
data class SessionSummary(
    val totalVolumeKg: Double,      // Σ 세트 볼륨 (웜업 제외)
    val totalSetCount: Int,         // 전체 세트 수 (웜업 포함)
    val workingSetCount: Int,       // 웜업 제외 세트 수
    val totalReps: Int,             // Σ reps (웜업 제외)
    val durationSec: Int,           // ended_at − started_at
    val avgIntensityPct: Double?,   // §3.1
    val bodyPartRatio: Map<String, Double>,  // 부위별 세트 비중(%)
)
```

**부위별 세트 비중 산출 규칙**

```
① 세트 → 종목 → exercise_body_part(role='PRIMARY') 로 부위 매핑
② 주동근이 2개 이상인 종목(예: 데드리프트)은 각 부위에 세트 1개씩 계상 (중복 계상)
③ 비중(%) = 부위별 세트 수 ÷ Σ(부위별 세트 수) × 100
```

> **②의 중복 계상**: 데드리프트를 등 0.5 / 하체 0.5로 분할하면 "등을 몇 세트 했나"의 직관과 어긋난다.
> 부위별 자극 빈도를 보는 것이 목적이므로 각 부위에 온전히 1세트로 계상하고, 합계가 100%가 되도록 마지막에 정규화한다.

**순 운동시간**: `ended_at − started_at`. 중간 이탈 시간을 차감하지 않는다(측정 불가·복잡도 대비 실익 없음).

## 5. 이전 기록 프리필 (FN-WRK-014) ★

세트 입력 터치 수를 좌우하는 핵심 로직이다(U3, REQ-WRK-003).

```
우선순위 1. 루틴 목표값이 있는가?
             ├─ target_weight_kg 존재      → 그 값 사용
             └─ target_percent_1rm 존재    → 종목추정1RM × 비율 (2.5kg 단위 반올림)
우선순위 2. 해당 종목의 직전 수행 기록(가장 최근 workout_log)
             → 세트 수·중량·횟수 구성을 그대로 복사 (웜업 포함)
우선순위 3. 기록 없음 (신규 종목)
             → 빈 세트 1개만 생성 (중량·횟수 미입력)
```

```kotlin
class PrefillSetsUseCase(
    private val workoutRepository: WorkoutRepository,
    private val oneRmCalculator: OneRepMaxCalculator,
) {
    suspend operator fun invoke(
        exerciseId: String,
        routineTarget: RoutineExercise?,
    ): List<WorkoutSet> {
        routineTarget?.let { t ->
            val weight = t.targetWeightKg
                ?: t.targetPercent1rm?.let { pct ->
                    val e1rm = workoutRepository.getEstimatedOneRm(exerciseId) ?: return@let null
                    roundToStep(e1rm * pct / 100.0, step = 2.5)     // 원판 단위로 반올림
                }
            return List(t.targetSetCount ?: 3) { i ->
                WorkoutSet(setNo = i + 1, weightKg = weight, reps = t.targetReps, setType = SetType.NORMAL)
            }
        }
        val last = workoutRepository.getLastPerformedSets(exerciseId)
        if (last.isNotEmpty()) return last.map { it.copyAsNew() }   // id 새로 발급, is_completed=false
        return listOf(WorkoutSet(setNo = 1, setType = SetType.NORMAL))
    }
}
```

| 규칙 | 내용 |
|---|---|
| 복사 시 초기화 | `is_completed=false`, `completed_at=null`, `memo=null`, `rpe=null` — **값만 복사, 수행 이력은 복사하지 않음** |
| %1RM 환산 반올림 | **2.5kg 단위** (원판 구성 현실 반영). 설정의 `weight_step_kg` 를 따름 |
| 직전 기록 조회 범위 | 최근 1건 (일자 내림차순). 회차가 여러 개면 가장 늦은 회차 |
| 프리필 근거 표시 | 화면 상단에 "직전: 7/28 80×8 (3세트)" 표기하여 값의 출처를 명시 |

## 6. 원판 계산기 (FN-TOL-008) ★

### 6.1 문제 정의

```
입력: 목표 중량 T (kg), 바 무게 B (kg), 보유 원판 { (무게 wᵢ, 한쪽 수량 cᵢ) }
목표: 한쪽에 올릴 원판 조합을 구한다.
      per_side = (T − B) / 2
제약: 각 원판은 한쪽 기준 cᵢ개까지만 사용 가능
목적: ① per_side 를 정확히 맞출 것  ② 불가하면 근사값 제시  ③ 원판 개수 최소화
```

### 6.2 알고리즘 — 제약 그리디 + 근사 탐색

```kotlin
object PlateSolver {

    data class Result(
        val plates: List<PlateCount>,   // 한쪽 기준 조합
        val actualTotalKg: Double,      // 실제 총 중량 (바 포함)
        val isExact: Boolean,
    )

    fun solve(targetKg: Double, barKg: Double, inventory: List<UserPlate>): List<Result> {
        val perSide = (targetKg - barKg) / 2.0
        if (perSide < 0) return emptyList()                 // 목표가 바보다 가벼움
        if (perSide == 0.0) return listOf(Result(emptyList(), barKg, isExact = true))

        val exact = greedy(perSide, inventory)
        if (exact != null) return listOf(exact.toResult(barKg, isExact = true))

        // 정확히 맞출 수 없으면 아래/위 근사 2안 제시
        val lower = greedyFloor(perSide, inventory)         // perSide 이하 최대
        val upper = nextAchievableAbove(perSide, inventory) // perSide 초과 최소
        return listOfNotNull(lower, upper).map { it.toResult(barKg, isExact = false) }
    }

    /** 큰 원판 우선. 수량 제약 하에서 잔여를 정확히 0으로 만들 수 있으면 반환 */
    private fun greedy(perSide: Double, inv: List<UserPlate>): Combo? {
        var remain = perSide
        val used = mutableListOf<PlateCount>()
        inv.sortedByDescending { it.plateWeightKg }.forEach { p ->
            val n = minOf((remain / p.plateWeightKg).toInt(), p.countPerSide)
            if (n > 0) { used += PlateCount(p.plateWeightKg, n); remain -= n * p.plateWeightKg }
        }
        return if (abs(remain) < EPSILON) Combo(used) else null
    }
}
```

> **왜 그리디로 충분한가**: 실제 원판 규격(20/15/10/5/2.5/1.25)은 **각 단계가 하위 조합으로 표현 가능한 정준 체계**에 가까워
> 그리디가 최적해를 준다. 다만 사용자가 임의 원판(예: 7kg)을 등록할 수 있으므로, 그리디 실패 시
> **DP(부분합) 백업 경로**를 두어 정확 조합 존재 여부를 재확인한다(원판 종류 ≤ 10, 수량 ≤ 10 → 탐색 공간 충분히 작음).

### 6.3 검증 케이스

| 목표 | 바 | 보유(한쪽) | 결과 |
|---:|---:|---|---|
| 100 | 20 | 20×2, 10×2, 5×2 | **정확** — 20×2 (한쪽 40kg) |
| 102.5 | 20 | 20×2, 1.25×2 | **정확** — 20×2 + 1.25×1 (41.25kg) |

## 7. 휴식 타이머 (FN-TOL-001~005)

### 7.1 시간 산출 원칙

```kotlin
// ❌ 금지 — 백그라운드에서 drift 발생
while (remain > 0) { delay(1000); remain-- }

// ✅ 기준 시각 델타 방식
val startElapsed = SystemClock.elapsedRealtime()   // 시스템 시계 변경·부팅 무관
fun remainMillis(): Long = targetMillis - (SystemClock.elapsedRealtime() - startElapsed)
```

| 항목 | 설계 |
|---|---|
| 시간 기준 | `SystemClock.elapsedRealtime()` — 사용자의 시계 변경, 타임존 변경에 영향받지 않음 |
| UI 갱신 | 200ms 주기 tick (표시 전용). **잔여 시간은 항상 델타로 재계산** |
| 백그라운드 | Foreground Service (`type=specialUse`) + 진행형 알림. 알림 기동에 실패해도 앱은 죽지 않고 타이머만 계속 간다 |
| 휴식시간 결정 | `exercise.default_rest_sec` → 없으면 `user_setting.default_rest_sec`(기본 90초) |
| 제어 | 일시정지(경과 시간 누적 보존) / 재개 / 건너뛰기 / ±15초 |
| 종료 통지 | 진동 + 소리 + 알림 (설정별 On/Off) |
| 다중 실행 | 새 세트 완료 시 **기존 타이머 즉시 취소 후 재시작** |

### 7.2 일시정지 처리

```kotlin
// 일시정지: 경과분을 accumulated 에 적립하고 기준 시각 초기화
fun pause()  { accumulatedMs += elapsedRealtime() - startElapsed; isPaused = true }
fun resume() { startElapsed = elapsedRealtime(); isPaused = false }
fun remain() = targetMs - accumulatedMs - if (isPaused) 0 else (elapsedRealtime() - startElapsed)
```

## 8. 개인기록(PR) 감지 (FN-RPT-016~017)

세트 저장 시점에 3종 PR을 판정한다.

| PR 유형 | 판정 대상 | 조건 |
|---|---|---|
| `MAX_WEIGHT` | `weight_kg` | 기존 최고 중량 초과 |
| `MAX_E1RM` | `estimate(w, r)` | 기존 최고 추정 1RM 초과 |
| `MAX_SET_VOLUME` | `w × r` | 기존 최고 단일세트 볼륨 초과 |

```kotlin
class DetectPersonalRecordUseCase(private val repo: WorkoutRepository) {
    suspend operator fun invoke(set: WorkoutSet, exerciseId: String): List<PersonalRecord> {
        if (set.setType == SetType.WARMUP) return emptyList()      // 웜업 제외
        if (!set.isCompleted) return emptyList()                   // 완료 세트만
        val w = set.weightKg ?: return emptyList()
        val r = set.reps ?: return emptyList()

        val current = repo.getCurrentPrs(exerciseId)
        return buildList {
            if (w > (current.maxWeight ?: 0.0))
                add(PersonalRecord(PrType.MAX_WEIGHT, w, repsAtRecord = r))
            OneRepMaxCalculator.estimate(w, r, formula)?.let { e1rm ->
                if (e1rm > (current.maxE1rm ?: 0.0))
                    add(PersonalRecord(PrType.MAX_E1RM, e1rm, repsAtRecord = r))
            }
            val vol = w * r
            if (vol > (current.maxSetVolume ?: 0.0))
                add(PersonalRecord(PrType.MAX_SET_VOLUME, vol, repsAtRecord = r))
        }
    }
}
```

| 규칙 | 내용 |
|---|---|
| 대상 | **완료(`is_completed=1`) + 웜업 아닌** 세트만 |
| 저장 | 기존 행 UPDATE가 아니라 **신규 INSERT** → 전체가 곧 갱신 이력 (FN-RPT-018) |
| 동률 | 초과(`>`)만 PR. 동일값은 갱신 아님 |
| 알림 | 수행 화면에서 스낵바 1회. 같은 세션 내 동일 유형 중복 알림은 마지막 것만 |
| 기록 수정/삭제 | PR 근거 세트가 삭제되면 해당 PR 행도 삭제하고 차순위를 재계산 |

## 9. 스트릭 (FN-CAL-008)

```
주간 달성 = 해당 주(월~일)의 COMPLETED 일지 수 ≥ user_setting.weekly_goal_count
스트릭    = 현재 주부터 과거로 거슬러 연속 달성한 주차 수
```

```kotlin
object StreakCalculator {
    fun calculate(completedDates: Set<LocalDate>, weeklyGoal: Int, today: LocalDate): Int {
        var streak = 0
        var weekStart = today.with(DayOfWeek.MONDAY)
        while (true) {
            val weekEnd = weekStart.plusDays(6)
            val count = completedDates.count { it in weekStart..weekEnd }
            val isCurrentWeek = weekStart == today.with(DayOfWeek.MONDAY)

            when {
                count >= weeklyGoal -> streak++
                // 진행 중인 주는 아직 미달이어도 스트릭을 끊지 않는다
                isCurrentWeek       -> { /* skip */ }
                else                -> return streak
            }
            weekStart = weekStart.minusWeeks(1)
        }
    }
}
```

> **진행 중인 주 예외 처리**가 핵심이다. 월요일에 앱을 열었을 때 "연속 기록 0주"로 표시되면
> 동기부여 기능이 오히려 역효과를 낸다.

| 이번 주 1회(진행 중), 지난 3주 각 3회 | **3** (이번 주 미판정) |
| 이번 주 3회, 지난 2주 각 3회, 그 전 주 2회 | **3** |

## 10. 초성 검색 (FN-EXR-008)

### 10.1 초성 추출

```kotlin
private val CHOSUNG = charArrayOf(
    'ㄱ','ㄲ','ㄴ','ㄷ','ㄸ','ㄹ','ㅁ','ㅂ','ㅃ','ㅅ',
    'ㅆ','ㅇ','ㅈ','ㅉ','ㅊ','ㅋ','ㅌ','ㅍ','ㅎ'
)

fun extractChosung(text: String): String = buildString {
    text.forEach { ch ->
        if (ch in '가'..'힣') {                    // 한글 음절
            append(CHOSUNG[(ch.code - 0xAC00) / 588])
        } else if (!ch.isWhitespace()) {
            append(ch.lowercaseChar())                      // 영문·숫자는 그대로
        }
    }
}
```

| 원문 | 초성 인덱스 |
|---|---|
| 벤치프레스 | `ㅂㅊㅍㄹㅅ` |
| 인클라인 덤벨프레스 | `ㅇㅋㄹㅇㄷㅂㅍㄹㅅ` |
| 랫풀다운 | `ㄹㅍㄷㅇ` |

### 10.2 검색 쿼리

```sql
SELECT * FROM exercise
WHERE is_active = 1
  AND ( name LIKE '%' || :q || '%'
     OR name_en LIKE '%' || :q || '%'
     OR name_chosung LIKE :chosungQ || '%' )      -- 초성은 전방 일치
ORDER BY
  CASE WHEN name LIKE :q || '%' THEN 0 ELSE 1 END,   -- 전방 일치 우선
  name
LIMIT 50;
```

| 규칙 | 내용 |
|---|---|
| 인덱스 컬럼 | `name_chosung` 은 **등록·수정 시 사전 계산**하여 저장(런타임 변환 금지 — 300ms 요구) |
| 초성 매칭 방식 | **전방 일치**. 중간 일치까지 허용하면 노이즈가 급증한다 (`ㅂㅊ` → 무관한 종목 다수) |

| 디바운스 | 200ms |
| 상한 | `LIMIT 50` |

## 11. 단위 변환 (REQ-CMN-003)

### 11.1 변환 상수 및 규칙

| 변환 | 상수 | 저장 단위 |
|---|---|---|
| kg ↔ lb | `1 kg = 2.20462262 lb` | **kg** |
| cm ↔ inch | `1 inch = 2.54 cm` | **cm** |
| km ↔ mile | `1 mile = 1.609344 km` | **km** |

```kotlin
object UnitConverter {
    fun kgToDisplay(kg: Double, unit: WeightUnit): Double = when (unit) {
        WeightUnit.KG -> round1(kg)
        WeightUnit.LB -> round1(kg * 2.20462262)
    }
    fun displayToKg(value: Double, unit: WeightUnit): Double = when (unit) {
        WeightUnit.KG -> value
        WeightUnit.LB -> value / 2.20462262        // ★ 반올림하지 않고 원값 저장
    }
}
```

| 규칙 | 내용 |
|---|---|
| **저장은 항상 SI** | DB에는 kg/cm/km만 저장한다 (P7) |
| **변환 위치** | Presentation 경계(ViewModel)에서만. Domain/Data는 SI만 취급 |
| **반올림 방향** | 표시 시 소수 1자리 반올림. **저장 시에는 반올림하지 않는다**(왕복 변환 오차 누적 방지) |
| **증감 단위** | kg 모드 2.5kg / lb 모드 5lb (사용자 설정으로 변경 가능) |

**왕복 변환 검증**: `displayToKg(kgToDisplay(100.0, LB), LB)` ≈ 100.0 (오차 < 0.05kg)

## 13. 점진적 과부하 자동 제안 (FN-RTN-014, Phase 3)

```
IF 직전 수행에서 모든 정상 세트가 목표 횟수를 달성했다면
   다음 목표 중량 = 직전 중량 + increment_kg
ELSE IF 목표 횟수 미달이 2회 연속이면
   디로드 제안: 직전 중량 × 0.9 (2.5kg 단위 반올림)
ELSE
   중량 유지, 횟수 목표 상향
```

```kotlin
class SuggestNextTargetUseCase {
    operator fun invoke(history: List<SessionResult>, rule: PeriodizationRule): Suggestion {
        val last = history.lastOrNull() ?: return Suggestion.NoChange
        return when {
            last.allWorkingSetsAchievedTargetReps ->
                Suggestion.IncreaseWeight(roundToStep(last.weightKg + rule.incrementKg, 2.5))
            history.takeLast(2).all { !it.allWorkingSetsAchievedTargetReps } ->
                Suggestion.Deload(roundToStep(last.weightKg * 0.9, 2.5))
            else -> Suggestion.KeepWeight
        }
    }
}
```

> 제안은 **제안일 뿐 자동 적용하지 않는다.** 프리필 값 위에 "▲ 82.5kg 제안" 배지로 표시하고 사용자가 채택 여부를 결정한다.

## 15. 동기화 충돌 해소 (FN-DAT-004)

```
resolve(local, server):
    IF local.updated_at > server.updated_at  → local 채택 (서버 UPDATE)
    IF local.updated_at < server.updated_at  → server 채택 (로컬 덮어쓰기)
    IF 같음                                   → 동일본, 무처리
    IF 한쪽에 tombstone 존재                   → ★ 삭제 우선
```

| 규칙 | 근거 |
|---|---|
| **LWW (Last-Write-Wins)** | REQ-DAT-002 명시. 단일 사용자 전제이므로 3-way merge의 복잡도가 실익을 초과 |
| **삭제 우선** | "지웠는데 되살아남"이 "지운 게 유지됨"보다 사용자 체감 손상이 크다 |
| **시각 기준** | `updated_at` 은 **단말 시각**이므로 기기 간 시계 오차가 있을 수 있다. 오차 5분 이상 감지 시 서버 시각으로 보정 후 재비교 |
| 부분 실패 | 레코드 단위 처리. 일부 실패가 배치 전체를 롤백시키지 않음 |
