> 상위 문서: [01.Analysis/05_데이터엔티티목록.md](../01.Analysis/05_데이터엔티티목록.md) (논리 모델 초안 24개 엔티티)

## 1. 설계 규약

### 1.1 명명 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 테이블 | `snake_case` 단수형 | `workout_set` |
| 컬럼 | `snake_case` | `weight_kg` |
| PK | `id` | |
| FK | `{참조테이블}_id` | `workout_log_id` |
| 불리언 | `is_` / `has_` 접두 (INTEGER 0/1) | `is_completed` |
| 단위 포함 컬럼 | 컬럼명에 단위 명시 | `weight_kg`, `distance_km`, `duration_sec` |
| 인덱스 | `idx_{테이블}_{컬럼…}` | `idx_workout_log_user_date` |
| Room Entity 클래스 | `{테이블}Entity` (PascalCase) | `WorkoutSetEntity` |

### 1.2 공통 컬럼 (동기화 대상 테이블 전체 적용)

| 컬럼 | 타입 | Null | 설명 |
|---|---|:--:|---|
| `id` | TEXT | N | **UUID v4**. 기기 간 충돌 없는 전역 식별자 (REQ-DAT-004 중복 방지) |
| `created_at` | INTEGER | N | 생성 시각 (epoch millis, UTC) |
| `updated_at` | INTEGER | N | 최종 수정 시각. **LWW 충돌 해소 기준** (REQ-DAT-002) |
| `is_dirty` | INTEGER | N | 로컬 전용. `1`=미동기화 변경분. 서버로 전송하지 않으며 PUSH 성공 시 `0` |

> **`is_dirty` 는 서버 스키마에 존재하지 않는다.** 로컬 델타 추출 전용 플래그다.

### 1.3 타입 매핑 (Room ↔ PostgreSQL)

| 논리 타입 | Room (SQLite) | PostgreSQL | Kotlin | 비고 |
|---|---|---|---|---|
| 식별자 | `TEXT` | `UUID` | `String` | 서버는 네이티브 UUID |
| 날짜 | `TEXT` | `DATE` | `LocalDate` | ISO-8601 `yyyy-MM-dd` |
| 시각 | `INTEGER` | `TIMESTAMPTZ` | `Instant` | 로컬은 epoch millis |
| 실수 | `REAL` | `NUMERIC(6,2)` | `Double` | 중량/둘레 등 |
| 정수 | `INTEGER` | `INTEGER` | `Int` | |
| 불리언 | `INTEGER` (0/1) | `BOOLEAN` | `Boolean` | |
| 열거 | `TEXT` | `VARCHAR(20)` | `enum class` | **코드값 문자열 저장** (수치 코드 금지 — 마이그레이션 안전) |
| 긴 문자열 | `TEXT` | `TEXT` | `String` | |

### 1.4 삭제 정책

| 유형 | 대상 | 처리 |
|---|---|---|
| **논리 삭제 (`is_active=0`)** | `exercise`, `routine`, `food` | 기록이 참조하는 마스터. 목록에서 숨기되 과거 기록의 표시명을 보존 (REQ-EXR-004, FN-RTN-004) |
| **물리 삭제 + tombstone** | `workout_log`, `workout_set`, `body_*`, `diet_*` 등 기록 | 삭제 시 `tombstone` 레코드 생성 → 서버로 전파 (FN-WRK-004, REQ-DAT-002) |
| **연쇄 삭제** | 부모 삭제 시 자식 | `ON DELETE CASCADE` (Room `ForeignKey.CASCADE`) + 자식 tombstone 일괄 생성 |

**3년치(30,000세트) 성능 검증 쿼리 — 반드시 `EXPLAIN QUERY PLAN` 확인**

```sql
-- 월간 캘린더 (인덱스 스캔이어야 함)
SELECT workout_date, COUNT(*) FROM workout_log
WHERE user_id = ? AND workout_date BETWEEN ? AND ? AND status = 'COMPLETED'
GROUP BY workout_date;

-- 종목별 볼륨 추이 (FN-RPT-008)
SELECT wl.workout_date, SUM(ws.weight_kg * ws.reps) AS volume
FROM workout_set ws
JOIN workout_log_exercise wle ON ws.log_exercise_id = wle.id
JOIN workout_log wl          ON wle.workout_log_id = wl.id
WHERE wle.exercise_id = ? AND wl.workout_date >= ? AND ws.set_type != 'WARMUP'
GROUP BY wl.workout_date ORDER BY wl.workout_date;
```

> **원칙**: 리포트 집계는 **전부 SQL `GROUP BY`** 로 수행한다. 세트 전체를 메모리로 로딩해 Kotlin에서 합산하는 구현을 금지한다.

## 5. Room 마이그레이션 정책 (REQ-NFR-006)

| 항목 | 규약 |
|---|---|
| 스키마 export | `room.schemaLocation` 활성 → `app/schemas/*.json` **VCS 커밋 필수** |
| `fallbackToDestructiveMigration` | **절대 금지**. 기록 유실은 본 앱에서 치명적 결함 |
| 마이그레이션 작성 | 버전 증가 시 `Migration(n, n+1)` 반드시 작성 |
| 마이그레이션 테스트 | `MigrationTestHelper` 로 **모든 인접 버전 쌍** 테스트. CI 필수 통과 항목 |
| 컬럼 추가 | `ALTER TABLE ADD COLUMN` + **NOT NULL이면 DEFAULT 필수** |
| 컬럼 삭제/타입 변경 | SQLite 제약상 `임시테이블 생성 → 데이터 복사 → 원본 DROP → RENAME` 4단계 |
| 자동 마이그레이션 | 단순 컬럼 추가는 `@AutoMigration` 허용. 데이터 변환이 필요하면 수동 작성 |

```kotlin
val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE workout_set ADD COLUMN rir INTEGER DEFAULT NULL")
    }
}
```

**DB 버전 이력 관리표** (릴리즈마다 갱신)

| DB Version | 앱 버전 | 변경 내용 | 마이그레이션 |
|---|---|---|---|
| 1 | 1.0.0 | 최초 스키마 (Phase 1 테이블 13종 — `exercise_reference` 포함) | — |
| 2 | (P2 예정) | `personal_record`, `body_*`, 동기화 컬럼 추가 | `MIGRATION_1_2` |
| 3 | (P3 예정) | `food`, `diet_*`, `body_photo` 추가 | `MIGRATION_2_3` |

## 6. 서버(PostgreSQL) 대응 스키마

| 항목 | 로컬(Room) | 서버(PostgreSQL) |
|---|---|---|
| 스키마 관리 | Room Migration | **Flyway** (`V1__init.sql`, `V2__…`) |
| PK 타입 | `TEXT` (UUID 문자열) | `UUID` |
| 시각 | `INTEGER` (epoch ms) | `TIMESTAMPTZ` |
| 테넌시 | 단일 사용자 | `user_id` 로 전 테이블 파티셔닝(논리) — **모든 쿼리에 `user_id` 조건 필수** |
| 미보유 테이블 | — | `sync_state`(로컬 전용), `note_fts`(로컬 전용) |
| 서버 전용 테이블 | — | `refresh_token`, `sync_audit` |
| 동기화 컬럼 | `is_dirty` (로컬 전용) | 없음 |

```sql
-- 서버 전용: Refresh Token
CREATE TABLE refresh_token (
    id          UUID PRIMARY KEY,
    user_id     UUID NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
    token_hash  VARCHAR(255) NOT NULL,
    expires_at  TIMESTAMPTZ  NOT NULL,
    revoked_at  TIMESTAMPTZ,
    device_info VARCHAR(255)
);
CREATE INDEX idx_refresh_token_user ON refresh_token(user_id);

-- 동기화 성능: 사용자별 증분 조회
CREATE INDEX idx_workout_log_sync ON workout_log(user_id, updated_at);
```

> **`user` 는 PostgreSQL 예약어**이므로 서버 테이블명은 `app_user` 로 한다. 앱↔서버 매핑은 DTO 레벨에서 처리한다.
