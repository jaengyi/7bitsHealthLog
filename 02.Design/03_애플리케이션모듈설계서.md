### 1.3 의존 규칙 (위반 시 컴파일 실패)

| 규칙 | 내용 |
|---|---|
| **R-1** | `:core:domain` 은 어떤 모듈에도 의존하지 않으며 `android.*` / `androidx.*` 를 import할 수 없다. (JVM Library 플러그인으로 강제) |
| **R-2** | `:feature:*` 는 `:core:data` / `:core:database` / `:core:network` 를 **직접 참조 금지**. Repository는 인터페이스(`:core:domain`)로만 접근한다. |
| **R-3** | `:feature:*` 간 상호 참조 금지. 화면 이동은 `:app` 의 NavHost에서 route 문자열로 연결한다. |
| **R-4** | `:core:designsystem` 은 도메인 모델을 알지 못한다(범용 컴포넌트만). 도메인을 아는 Composable은 `:core:ui` 에 둔다. |
| **R-5** | `:core:database` 의 Entity는 모듈 밖으로 노출되지 않는다(`internal`). 경계는 항상 Domain Model. |

## 3. 의존성 주입 (Hilt)

### 3.1 컴포넌트 스코프

| 스코프 | 대상 |
|---|---|
| `@Singleton` | Room DB, DAO, Retrofit, OkHttp, DataStore, Repository 구현, SyncOrchestrator |
| `@ViewModelScoped` | ViewModel 전용 협력 객체(거의 사용하지 않음) |
| 무스코프 | UseCase — 상태가 없으므로 매번 생성 (생성 비용 무시 가능) |

### 3.2 모듈 배치

| Hilt 모듈 | 위치 | 제공 대상 |
|---|---|---|
| `DatabaseModule` | `:core:database` | `MyFitDatabase`, 각 DAO |
| `NetworkModule` | `:core:network` | `OkHttpClient`, `Retrofit`, `MyFitApi`, `Json` |
| `DataStoreModule` | `:core:data` | `DataStore<Preferences>` |
| `RepositoryModule` | **`:app`** | Repository 인터페이스 ↔ 구현 바인딩 (`@Binds`) |
| `DispatcherModule` | `:core:common` | `@IoDispatcher`, `@DefaultDispatcher`, `@MainDispatcher` |

```kotlin
// :app  RepositoryModule.kt  — 계층 결합을 여기 한 곳에 격리
@Module
@InstallIn(SingletonComponent::class)
abstract class RepositoryModule {
    @Binds @Singleton
    abstract fun bindWorkoutRepository(impl: WorkoutRepositoryImpl): WorkoutRepository
    @Binds @Singleton
    abstract fun bindExerciseRepository(impl: ExerciseRepositoryImpl): ExerciseRepository
    // …
}
```

```kotlin
// :core:common  Dispatchers 규약 — 테스트에서 TestDispatcher로 치환
@Retention(AnnotationRetention.RUNTIME) @Qualifier annotation class IoDispatcher
@Retention(AnnotationRetention.RUNTIME) @Qualifier annotation class DefaultDispatcher
```

> **원칙**: UseCase·Repository 내부에서 `Dispatchers.IO` 를 **직접 호출하지 않는다.** 반드시 주입받은 Dispatcher를 사용한다(테스트 가능성).

### 4.2 Composable 규칙

| 규칙 | 내용 |
|---|---|
| **상태 호이스팅** | `XxxScreen(uiState, onAction)` 형태의 **stateless** Composable을 항상 분리한다. ViewModel을 받는 `XxxRoute`가 이를 감싼다. Preview는 stateless 쪽에 작성 |
| **Preview 필수** | 화면당 최소 2개(라이트/다크). 데이터가 많은 화면은 빈 상태 Preview 추가 |
| **`remember` 남용 금지** | 파생 값은 `derivedStateOf`, 목록은 `key` 지정 |
| **`LazyColumn` key** | 반드시 안정 ID(UUID) 지정 — 세트 삭제 시 리컴포지션 오류 방지 |
| **이벤트 수집** | `LaunchedEffect` + `repeatOnLifecycle(STARTED)` 로 `events` 수집 |

## 5. 네비게이션 설계

### 5.1 최상위 구조 — 하단 탭 5개

```
┌───────────────────────────────────────────────┐
│                 NavHost (:app)                │
│                                               │
│  startDestination = 온보딩 완료 ? Home : Onboarding │
├───────────────────────────────────────────────┤
│  [홈]   [캘린더]   [＋]   [루틴]   [더보기]      │
│   🏠      📅      기록     📋      ☰          │
└───────────────────────────────────────────────┘
```

| 탭 | 시작 화면 | 비고 |
|---|---|---|
| 홈 | `SCR-CMN-001` 홈 대시보드 | 오늘 운동·다음 루틴·주간 요약 |
| 캘린더 | `SCR-CAL-001` 월간 캘린더 | |
| **＋ 기록** | 오늘 일지로 진입 (`SCR-WRK-001`) | 중앙 FAB형 탭. 가장 빈번한 동선을 1탭으로 |
| 루틴 | `SCR-RTN-001` 루틴 목록 | |
| 더보기 | `SCR-CMN-003` 마이페이지 | 분석·신체·식단·도구·설정 진입 허브 |

> 분석/신체/식단/도구는 탭을 5개로 유지하기 위해 **더보기 허브** 하위로 배치한다.
> 단, 분석 리포트는 홈 대시보드에서도 바로가기를 제공한다.

### 5.2 Type-safe Route 정의

```kotlin
// :feature:workout/navigation/WorkoutNavigation.kt
@Serializable data class WorkoutLogRoute(val date: String, val sessionNo: Int = 1)
@Serializable data class SetInputRoute(val logExerciseId: String)
@Serializable data class WorkoutSessionRoute(val logId: String)
@Serializable data class SessionSummaryRoute(val logId: String)

fun NavGraphBuilder.workoutGraph(navController: NavController) {
    composable<WorkoutLogRoute> { WorkoutLogRoute(...) }
    composable<SetInputRoute>   { SetInputRoute(...) }
    composable<WorkoutSessionRoute> { WorkoutSessionRoute(...) }
    composable<SessionSummaryRoute> { SessionSummaryRoute(...) }
}
```

- Navigation Compose **type-safe API**(`@Serializable` route 객체)를 사용한다. 문자열 route 수동 조립을 금지한다.
- 각 feature 모듈이 자신의 `NavGraphBuilder` 확장 함수를 노출하고, `:app` 의 `MyFitNavHost` 가 이를 조립한다. → **R-3(피처 간 참조 금지)** 를 지키면서 화면 이동 가능.

## 6. 백그라운드 작업 설계

| 작업 | 실행 주체 | 트리거 | 제약 조건 | 관련 기능 |
|---|---|---|---|---|
| 휴식 타이머 | **Foreground Service** (`RestTimerService`) | 세트 완료 체크 | — | FN-TOL-001~005 |
| 서버 동기화 | `SyncWorker` (WorkManager) | ① 앱 포그라운드 진입 ② 15분 주기 ③ 네트워크 복구 | `NetworkType.CONNECTED`, 지수 백오프 재시도 | FN-DAT-002~005 |
| 자동 백업 | `AutoBackupWorker` | 1일 1회 주기 | `requiresBatteryNotLow`, 최근 5개 보관 | FN-DAT-009 |
| 미기록 리마인더 | `ReminderWorker` | 계획 일자 지정 시각 | — | FN-TOL-012 |
| 종목 마스터 초기 적재 | `AppInitializer` (1회성) | 최초 실행 | — | FN-EXR-001 |

```kotlin
// SyncWorker 등록 예
val syncRequest = PeriodicWorkRequestBuilder<SyncWorker>(15, TimeUnit.MINUTES)
    .setConstraints(Constraints.Builder().setRequiredNetworkType(NetworkType.CONNECTED).build())
    .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 30, TimeUnit.SECONDS)
    .build()
workManager.enqueueUniquePeriodicWork("sync", ExistingPeriodicWorkPolicy.KEEP, syncRequest)
```

> 동기화 실패는 **사용자에게 노출하지 않는다**(P2 원칙). 연속 실패가 임계치를 넘을 때만 설정 화면에 상태 배지로 표시한다.

## 7. 오류 처리 규약

| 계층 | 처리 방식 |
|---|---|
| Data | 예외를 잡아 `AppResult.Failure(AppError.*)` 로 변환. 예외를 위로 던지지 않는다 |
| Domain | `AppResult` 를 그대로 전달하거나 도메인 규칙 위반을 `Validation` 으로 생성 |
| Presentation | `AppError` → `UiText`(문자열 리소스 ID) 변환 후 스낵바/인라인 메시지 |

> **로컬 DB 작업 실패는 치명적 사건**으로 간주하여 Timber로 기록하고 사용자에게 명시적으로 알린다(기록 유실 위험). 반대로 **네트워크 실패는 무음 처리**한다.

## 8. 국제화 / 리소스 규약 (REQ-CMN-006)

| 항목 | 규약 |
|---|---|
| 문자열 | 모든 사용자 노출 문자열은 `strings.xml`. 코드 내 하드코딩 금지(detekt 규칙으로 검출) |
| 기본 로케일 | `ko` (values/) · 확장 대상 `en` (values-en/) |
| 문자열 키 | `{화면}_{용도}` — `workout_log_empty_message`, `common_action_save` |

| 단위 표기 | 문자열 리소스 밖에서 조립 금지 — `@string/unit_kg_format` (`%1$s kg`) 사용 |
| 복수형 | `plurals.xml` 사용 (`%d세트`) |
