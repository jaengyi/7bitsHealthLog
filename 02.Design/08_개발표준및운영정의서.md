### 1.3 Kotlin 작성 원칙

| # | 원칙 | 이유 |
|---|---|---|
| K1 | **`!!` 사용 금지** | detekt 로 검출. nullable은 `?.let`, `requireNotNull(msg)`, 엘비스로 처리 |
| K2 | **불변 우선** | `val` 기본, `List`(불변) 노출. `var`/`MutableList`는 지역 범위에서만 |
| K3 | **`data class` 로 상태 표현** | `copy()` 기반 상태 전이. 부분 갱신이 안전 |
| K4 | **sealed interface 로 분기 표현** | `when` 이 exhaustive → 케이스 누락을 컴파일러가 잡음 |
| K5 | **확장 함수는 `:core:common` 에만** | 프로젝트 전역 확장이 여기저기 흩어지는 것 방지 |
| K6 | **Dispatcher 직접 호출 금지** | 주입받은 `@IoDispatcher` 사용 (테스트 치환 가능) |
| K7 | **`runBlocking` 은 테스트에서만** | 프로덕션 코드 사용 금지 |
| K8 | **매직 넘버 금지** | 상수화. `2.5` → `DEFAULT_WEIGHT_STEP_KG` |
| K9 | **주석은 "왜"만** | "무엇"은 코드가 말한다. 비자명한 결정·트레이드오프만 주석 |
| K10 | **문자열 하드코딩 금지** | 사용자 노출 문자열은 전부 `strings.xml` |

### 1.4 Compose 작성 원칙

| # | 원칙 |
|---|---|
| C1 | **stateless/stateful 분리** — `XxxRoute(viewModel)` → `XxxScreen(uiState, onAction)` |
| C2 | **`Modifier` 파라미터 필수** — 모든 public Composable의 두 번째 파라미터로 `modifier: Modifier = Modifier` |
| C3 | **`LazyColumn` key 지정 필수** — 안정 ID(UUID). 미지정 시 삭제·정렬에서 상태 오염 |
| C4 | **`Preview` 최소 2개** — 라이트/다크. 목록 화면은 빈 상태 Preview 추가 |
| C5 | **ViewModel을 하위 Composable에 전달 금지** — 최상위에서만 주입 |
| C6 | **부수효과는 전용 API로** — `LaunchedEffect`, `DisposableEffect`. Composable 본문에서 직접 실행 금지 |
| C7 | **파생 상태는 `derivedStateOf`** — 불필요한 리컴포지션 억제 |
| C8 | **색상·치수는 토큰 참조** — `MaterialTheme.colorScheme.*`, `Dimens.*`. 리터럴 금지 |

### 2.2 브랜치 전략

개인 프로젝트 규모에 맞춘 **경량 GitHub Flow**를 사용한다(GitFlow는 과함).

```
main ────●────────●────────●────────●──▶   항상 배포 가능 상태 / 태그 = 릴리즈
          \      /          \      /
  feature/  ●──●     feature/ ●──●
```

| 브랜치 | 용도 | 명명 |
|---|---|---|
| `main` | 배포 가능 상태. **직접 커밋 금지**(PR 병합만) | — |
| `feature/*` | 기능 개발 | `feature/wrk-set-input` (기능ID 기반) |

| `docs/*` | 문서 작업 | `docs/design-api` |
| `chore/*` | 빌드·의존성·설정 | `chore/bump-agp` |

### 2.3 커밋 메시지 (Conventional Commits)

```
<type>(<scope>): <제목 — 한글, 명령형, 50자 이내>

<본문 — 무엇을 왜 바꿨는지. 어떻게는 코드가 설명>

Refs: FN-WRK-009, REQ-WRK-003
```

| type | 용도 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 |
| `refactor` | 동작 변경 없는 구조 개선 |
| `perf` | 성능 개선 |
| `test` | 테스트 추가·수정 |
| `chore` | 빌드·의존성·설정 |

**scope**: 모듈명 또는 도메인 코드 (`workout`, `exercise`, `sync`, `api`, `db`)

```
feat(workout): 세트 입력 시 300ms 디바운스 자동 저장 구현

명시적 저장 버튼 없이 입력 즉시 영속화한다. 연타 입력 시 DB 쓰기가
폭주하므로 300ms 디바운스를 적용하고, UI는 낙관적 갱신으로 100ms 이내
반영을 보장한다.

Refs: FN-WRK-031, REQ-WRK-011, REQ-NFR-001
```

> **`Refs:` 트레일러를 반드시 남긴다.** 요구사항 ↔ 커밋 추적성이 확보되어야
> 3년 뒤에 "이 로직이 왜 이렇게 되어 있나"를 정의서에서 역추적할 수 있다.

## 4. CI/CD

### 4.1 파이프라인

```
Push / PR
   │
   ├─▶ [Lint]     ktlintCheck + detekt
   ├─▶ [Build]    assembleDebug
   ├─▶ [Test]     testDebugUnitTest + Room Migration Test
   ├─▶ [Coverage] Domain 계층 80% 미만이면 실패
   └─▶ [Report]   결과 PR 코멘트

Tag v*.*.*
   │
   ├─▶ [App]  assembleRelease → 서명 → GitHub Release 첨부
   └─▶ [API]  Docker 이미지 빌드/푸시 → 서버 배포
```

### 4.2 GitHub Actions — 앱 CI

```yaml
name: android-ci
on:
  push:    { branches: [main] }
  pull_request:
jobs:
  verify:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: 03.Implement/myfit-android } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17', cache: gradle }
      - name: Lint
        run: ./gradlew ktlintCheck detekt
      - name: Unit Test
        run: ./gradlew testDebugUnitTest
      - name: Migration Test
        run: ./gradlew :core:database:testDebugUnitTest --tests '*MigrationTest'
      - name: Coverage Verify
        run: ./gradlew :core:domain:koverVerify      # 80% 미만 시 실패
      - name: Build
        run: ./gradlew assembleDebug
      - uses: actions/upload-artifact@v4
        if: failure()
        with: { name: test-reports, path: '**/build/reports/**' }
```

### 4.3 서버 배포

```bash
# 05.Deploy/deploy.sh
set -euo pipefail

VERSION="${1:?usage: deploy.sh <version>}"
cd /opt/myfit

# ① 배포 전 DB 백업 (롤백 대비)
docker compose exec -T db pg_dump -U "$DB_USER" -d myfit -Fc \
  > "./backup/pre-deploy_$(date +%Y%m%d_%H%M%S).dump"

# ② 이미지 갱신 및 재기동 (Flyway가 스키마 마이그레이션 수행)
API_VERSION="$VERSION" docker compose pull api
API_VERSION="$VERSION" docker compose up -d api

# ③ 헬스체크 (30초 대기)
for i in $(seq 1 15); do
  if curl -fsS http://127.0.0.1:8080/actuator/health | grep -q '"status":"UP"'; then
    echo "deploy ok: $VERSION"; exit 0
  fi
  sleep 2
done

echo "health check failed — rolling back" >&2
API_VERSION="$(cat .last-good-version)" docker compose up -d api
exit 1
```

| 원칙 | 내용 |
|---|---|
| **배포 전 백업 필수** | 스키마 마이그레이션 실패 시 복구 경로 확보 |
| **헬스체크 실패 시 자동 롤백** | 직전 정상 버전 태그로 재기동 |
| **앱 하위 호환** | 서버는 항상 **직전 앱 버전과 호환**되어야 한다. 앱 강제 업데이트는 최후 수단 |
| **다운타임 허용** | 개인 사용이므로 무중단 배포는 불필요. 단 배포는 새벽 시간대 수행 |

## 6. 백업 및 복구 정책

| 대상 | 주기 | 보관 | 위치 | 근거 |
|---|---|---|---|---|
| **단말 자동 백업** (JSON) | 1일 1회 | **최근 5개** | 앱 전용 저장소 | FN-DAT-009 |
| **단말 수동 백업** | 사용자 실행 | 무제한 | SAF 선택 경로 | FN-DAT-006 |
| **서버 DB 덤프** | 1일 1회 | **14일** | `/opt/myfit/backup` | REQ-NFR-010 |
| **배포 전 덤프** | 배포 시마다 | 최근 10개 | 동일 | §4.3 |

**복구 시나리오**

| 상황 | 절차 |
|---|---|
| 앱 삭제 후 재설치 | ① 로그인 → 전체 Pull 또는 ② 백업 JSON 복구 |
| 기기 변경 | 로그인 → 전체 Pull (UUID 기준 중복 없음, FN-DAT-010) |
| 잘못된 대량 삭제 | 최근 자동 백업 JSON에서 **병합 모드** 복구 |
| 서버 DB 손상 | `pg_restore` 로 직전 덤프 복구 → 앱에서 Push로 델타 보정 |

> **복구 모드 2종** (FN-DAT-007): **병합**(기존 유지 + 없는 것만 추가) / **대체**(전체 삭제 후 복구).
> 대체 모드는 2단계 확인을 요구한다.

## 7. 보안 운영 수칙 (REQ-NFR-004)

| 항목 | 수칙 |
|---|---|
| 비밀값 | 키스토어·OAuth 키·DB 비밀번호·JWT 시크릿은 **VCS 커밋 금지**. `local.properties` / `.env`(600) / CI Secret |
| 키스토어 백업 | 릴리즈 키스토어는 별도 오프라인 매체 2곳에 보관 (분실 시 앱 업데이트 불가) |
| TLS | Let's Encrypt 자동 갱신(certbot). 만료 7일 전 알림 |
| 서버 접근 | SSH 키 인증만 허용, 비밀번호 로그인 비활성, fail2ban |
| 포트 노출 | DB는 외부 미노출, API는 `127.0.0.1` 바인딩 후 nginx 경유만 |
| 의존성 취약점 | 분기별 `dependencyUpdates` + GitHub Dependabot 확인 |
| 신체 사진 | 앱 전용 내부 저장소, MediaStore 미등록, **EXIF 제거 후 저장**, `allowBackup=false` |

## 8. 저작권 및 라이선스 준수 (REQ-NFR-009)

| 항목 | 수칙 |
|---|---|
| **금지** | 상용 앱의 UI 디자인·아이콘·동작 애니메이션·음식 DB 등 저작물 복제 |
| 종목 설명 | **자체 작성** 또는 공공데이터·오픈라이선스(CC0/CC-BY) 자료만 사용 |
| **자세 가이드 이미지** | 자체 제작 또는 오픈라이선스(CC0/CC-BY) 자료만 내장. **출처·라이선스를 `04.Test/assets-license.csv` 에 종목 단위로 기록**하고 앱 정보 화면에 고지 |
| **자세 영상** | 영상 파일을 **복제·저장·재인코딩하지 않는다.** 외부 영상 서비스의 공식 임베드 플레이어 또는 링크로만 제공하며, DB에는 URL·videoId만 보관 |
| 영상 링크 선별 | 임베드가 허용된 영상만 기본 제공 목록에 포함. 임베드 차단 영상은 외부 앱 실행으로만 연결 |
| 음식 데이터 | 식품의약품안전처 식품영양성분 공공데이터만 사용, 출처 표기 (`food.source='MFDS'`) |
| 아이콘 | Material Symbols(Apache 2.0) 또는 자체 제작 |
| 폰트 | 오픈 라이선스(SIL OFL 등)만 |
| OSS 고지 | 앱 정보 화면에 **오픈소스 라이선스 목록** 표시 (`aboutlibraries` 등으로 자동 생성) |
| 참고 영상 | URL 링크만 저장. **영상 파일을 앱에 내장하지 않는다** (FN-EXR-004) |
| 배포 | 개인 사용 목적. **Play 스토어 배포·상업화 시 저작권·개인정보 처리방침 별도 검토 필요** |
